## 先理解：仓库到底是什么

GitHub 仓库就是一个在线项目文件夹。里面可以是说明书、AI 技能、笔记素材，也可以是网站程序。下载不等于安装，安装不等于已经接好了所需服务。

- README.md：给人看的介绍和使用说明。
- SKILL.md：让 AI 按特定方法办事的说明书；要放进支持技能的 AI 工具里使用。
- references/：技能执行时查阅的详细规则、题库和模板。
- agents/openai.yaml：技能在对应工具里的名称、简介等展示信息。
- app/、src/、package.json：通常意味着有应用代码，需要准备运行环境。
- .md：普通文字文档，可用文本编辑器或 Obsidian 阅读。
- Star：收藏项目。Fork：在自己的 GitHub 账号下建立项目分支。Clone：把仓库及版本历史下载到电脑。这三个操作都不等于把项目运行起来。

## 你现在打开的四个内容技能，分别怎么用

| 技能 | 需要你提供什么 | 得到什么 | 可以怎么说 |
|---|---|---|---|
| viral-pattern-analysis | 可完整读取的高表现素材；跨作者候选规律至少需要两个作者、两条独立素材 | 证据底稿、标题/开头/正文规律及索引 | “分析这批素材，区分跨作者规律、单个作者习惯和单条观察。” |
| topic-generation-workflow | 明确的一批素材，最好有已有定位和历史选题 | 有来源和素材去向记录的选题报告 | “根据这个素材文件夹生成候选选题，并说明哪些可以马上写、哪些还缺材料。” |
| content-production-workflow | 已确定的选题、平台或形式，以及相关资料或自己的口述 | 素材包、口述原文、结构、AI 初稿、审核和用户编辑稿，按所请求阶段生成 | “这个题我想讲，但没整理好。先一次问我一个问题，帮我把自己的经历说清楚，再按我的要求写稿。” |
| writing-preference-learning | 同一篇的 AI 初稿和自己修改或认可的版本 | 改稿差异证据和候选表达偏好 | “对比这两份稿子，学习这次改稿，把单篇事实修正和长期表达偏好分开。” |

四个技能不负责采集素材，也不自动发布。它们不会因为安装完成就拥有你的背景和素材。改稿学习把偏好写成可读取的规则文件，不是在训练或永久修改模型本身；候选规则需要确认后才进入正式偏好。

## 推荐的第一轮使用路线

1. 先安装通用账号定位技能，以及四个内容工作流技能。
2. 准备一个自己的内容工作文件夹，让 AI 把自己的资料写在这里。不要把作者已有背景当成自己的背景。
3. 用定位技能梳理经历、业务、受众和内容方向；没有产品可如实记录暂无。
4. 已经有选题，就直接试口述共创；还没有选题，再准备素材并调用选题技能。
5. 让 AI 生成一篇初稿，自己修改用户编辑稿，并保留原始 AI 初稿。
6. 调用改稿学习，选择值得长期保留的表达习惯。

首轮成功标准：有自己的定位资料，完成一篇含自己真实观点或经历的稿件，能找到 AI 初稿与修改稿。后续再考虑采集自动化和视频制作。

安装后按工具提示重新加载技能或开启新对话。随后可以说：

```text
使用 account-positioning-interview，先读取我指定的内容工作文件夹，帮我梳理自己的账号背景。缺什么就一次问我一个问题，没有的信息不要替我编。
```

有选题后可以说：

```text
使用 content-production-workflow。我要做一条口播视频，选题是【填入选题】。先整理相关材料，再通过提问补足我的观点和经历，最后根据我的确认生成初稿。
```

安装方式依据上述两个仓库自己的 README；是否可用以安装后实际识别和运行结果为准。

## 几个容易误判的地方

- “AI 全自动”不代表已经全流程完成。当前 Ai-auto-content 的 README 将写作、配图、发布列为 not_started；本机调度使用 Mac 的 LaunchAgent，你这台 Windows 不能照搬该部分。
- Ai-news 的演示模式和真实数据模式不同。作者的验收文档仍列出 YouTube 授权、Get 云端接口以及 AI Provider 等待验证项；作者机器上通过的连接也不等于你这台电脑已接通。
- AI-Content-System 实际提交的目录比规划中的完整流程少；不能把说明中的复盘等目录视为已有成品。
- talking-head-chatcut 依赖 ChatCut 配套工具。技能是操作规则，不会自带一个完整剪辑软件。
- 不需要为了使用前两个技能先学会编程，也不需要先搭建所有网站项目。
