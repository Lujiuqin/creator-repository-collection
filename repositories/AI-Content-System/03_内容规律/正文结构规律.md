# 正文结构规律

## 候选规律

### 规律 1：【问题或局限 → 关键判断 → 方法展开 → 价值与行动】
- 大白话解释：结构顺序是先说当前做法哪里卡住，再把问题重新定义成一个更关键的判断，然后逐层讲框架、步骤或系统，最后回到它能解决什么并给出下一步动作。
- 适合什么内容：AI 基础科普、工作流方法、工具能力变化、从常见误区进入的教程。
- 不适合什么内容：没有明确问题、只有功能罗列、还无法给出方法或边界的内容。
- 不可照搬点：不能先制造一个并不存在的痛点；方法部分必须真正回答前面提出的问题，结尾也不能跳到无关转化。

### 规律 2：【交代对象或测试 → 分维度给证据 → 同时讲优缺点 → 最后判断】
- 大白话解释：结构顺序是先说明在评谁、依据什么或做了什么测试，再按能力、质量、速度、成本等维度展开，既写优势也写风险，最后才给定位或选择建议。
- 适合什么内容：模型评测、多产品横评、行业案例分析、工具成本与质量判断。
- 不适合什么内容：没有统一测试条件、只有宣传材料、无法获得负面结果或限制信息的内容。
- 不可照搬点：维度顺序应跟真实任务相关；不能为了形式完整虚构优缺点，也不能把不同来源、不同条件的数据直接放在一起比较。

### 规律 3：【先给总框架 → 编号拆成并列模块 → 逐项展开 → 汇总建议】
- 大白话解释：结构顺序是先告诉读者内容被分成几层、几项或几个部分，再用编号保持平行顺序，每一项继续解释工具、能力、步骤或结果，最后用总表、结论或建议收口。
- 适合什么内容：工具分类、能力清单、功能介绍、多维测评、步骤教程、阶段盘点。
- 不适合什么内容：只有一个核心观点、各部分没有同一分类口径、需要按故事因果推进的内容。
- 不可照搬点：编号数量不是越多越好；各模块必须处在同一层级，不能把功能、结论、案例和促销信息混成并列项。

### 规律 4：【真实经历 → 具体卡点或实验 → 执行过程 → 结果与经验 → 互动动作】
- 大白话解释：结构顺序是先交代作者真实做过什么，再写过程中遇到的混乱、失败或感受，接着还原解决步骤，最后提炼经验，并以试用、讨论或阶段总结结束。
- 适合什么内容：个人实测、工作流搭建、项目复盘、月度 AI 使用记录。
- 不适合什么内容：作者没有参与过程、只有二手信息、无法公开过程与结果的内容。
- 不可照搬点：必须区分真实经历、个人判断和外部事实；不能把素材作者的故事当成自己的经历，也不能只写情绪而省略执行过程。

### 规律 5：【文字先搭主线 → 图片逐页补过程、证据或界面 → 结尾再收束】

- 适合什么内容：图文测评、操作教程、系统展示、数据案例、需要界面或产物证明的工具内容。
- 不适合什么内容：图片与文字只是重复、截图无法看清、没有足够材料支持逐页展开的内容。
- 不可照搬点：图片顺序必须服务同一条逻辑线；不能在文字里下结论，却把关键证据藏在无法辨认的截图中。

### 规律 6：【讲完能力或步骤，马上接具体场景和例子】
- 大白话解释：结构顺序是先说一个能力、原则或步骤，再用电商、教育、内容运营、写作等具体场景说明它怎么用，之后才继续下一个能力或回到总判断。
- 适合什么内容：概念科普、功能解读、工作流教程、面向新人的 AI 入门内容。
- 不适合什么内容：没有真实场景材料、案例条件与目标读者不一致、只需发布简短事实更新的内容。
- 不可照搬点：案例中的行业、结果和效果不能替换名称后直接复用；只能使用自己有证据的真实场景。

### 规律 7：【结尾给与内容目标一致的具体下一步】
- 大白话解释：结构顺序是在总结之后告诉读者接下来可以做什么：收藏分类图、用免费额度跑真实任务、回答需求问题、申请试用、分享卡点或直接体验产品。动作与正文用途相连，而不是只喊口号。
- 适合什么内容：教程、工具选择、产品展示、需要收集反馈或推动试用的内容。
- 不适合什么内容：风险尚未说清、动作与正文价值无关、读者执行后可能产生未说明成本的内容。
- 不可照搬点：收藏、评论、试用和付费是不同目标，应根据内容真实目的选择一个主要动作；涉及产品体验时要说明条件和成本。

### 规律 8：【AI 先执行 → 暴露错误或边界 → 人工核对与修正 → 再交付或判断】
- 大白话解释：结构顺序不是把 AI 输出直接当结果，而是先展示自动执行，再指出幻觉、事实错误、画面问题或识别误差，接着加入人工核验和定向修改，最后才形成可用交付或选择结论。
- 适合什么内容：Agent 测评、自动化工作流、AI 视频生产、模型可靠性与业务落地分析。
- 不适合什么内容：没有实际测试过程、无法人工核验结果、只展示理想演示的内容。
- 不可照搬点：不能预设一定会出现某种错误；需要如实记录测试条件、具体问题和人工介入位置。
