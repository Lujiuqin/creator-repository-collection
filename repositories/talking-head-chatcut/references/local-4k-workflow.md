# 本地 4K 主素材工作流

## 适用范围与默认决策

本账号后续主口播素材默认由用户在 ChatCut Desktop 中直接导入原始 4K 文件，AI 再通过 ChatCut 插件读取项目、转写和编辑时间线。只要用户没有明确改用云端上传，本流程就是 4K 项目的默认分支，不要反复询问导入方式。

当前版本中，插件媒介导入可能为兼容性生成不超过 1920 像素长边的副本。**在没有新的实测结果证明 4K 能原样保留之前，AI 不得用 `chatcut:asset-import` 或 `import_media` 重新导入 4K 主母版，也不得把 1920×1080 素材放进 3840×2160 画布后宣称保留了 4K。** 图片、贴图、音乐和其他不承担 4K 主母版职责的素材仍按对应 ChatCut Skill 正常导入。

## 2026-08-06 已验证基线

测试项目：`test-4K`。测试源文件由 DJI Pocket 4 录制，源参数为 3840×2160、HEVC Main 10、50 fps，视频码率约 37.7 Mbps，文件约 2.30 GB。

本次已经直接验证：

- 用户通过 ChatCut Desktop 导入后，ChatCut 资产元数据仍为 3840×2160，没有被登记成 1920×1080。
- 插件能够列出该本地资产、读取完整转写，并执行基于转写的 AI 精剪。
- 在复制时间线 `4K AI操作测试` 上，AI 将画布设置为 3840×2160，完成开头重复口播删除，形成两个连续视频项，并添加音频交叉淡化。
- ChatCut Desktop 能打开该复制时间线并正常播放编辑后的本地 4K 素材，没有出现黑屏或素材离线。
- 该资产被连接器标记为 `local-only`；云端时间线截图和云端画面渲染因为没有远程源 URL 而不可用。

由本次验证可以确认：`local-only` **不是不可剪辑、不是素材损坏，也不是 4K 降级**。它只表示素材字节仍在用户电脑上。项目读取、转写读取、脚本精剪、时间线 item/track 操作、字幕、贴图、MG、转场等可编辑操作仍可执行；这些可见效果必须在每个项目中通过桌面预览检查实际像素。

本次尚未证明“4K 最终导出成功”。因此未来 AI 不得引用本次测试宣称 4K 导出已经验证；只有检查真实导出文件后才能给出该结论。

## S0：接管本地 4K 项目

1. 先定位用户指定或当前活动的 ChatCut 项目，不要新建同名项目，也不要重新导入主素材。
2. 用 `browse_assets`、`read_project` 或当前 manifest 的等价工具读取资产和时间线，确认主素材文件名、`assetId`、分辨率、时长、转写状态和远程就绪状态。
3. 若 AI 能读取原始本地路径，用 `ffprobe` 做只读核验，记录编码、位深、分辨率、帧率、码率、时长和文件大小；不得用本地 ffmpeg 转码、合成或替代 ChatCut 编辑。
4. 资产分辨率必须至少等于目标画布。目标是 4K 而 ChatCut 资产只显示 1920×1080 时，立即停止把它当 4K 母版，告诉用户在桌面版重新导入原文件；不得靠放大冒充 4K。
5. 明确记录 `assetReadiness=remote-ready|local-only`。`local-only` 是预期状态，不触发重新上传、重新关联或降级画布。只有用户明确需要云端渲染、云端字节分析或跨电脑继续编辑时，才说明重新关联会上传大文件并征求用户选择。
6. 核对时间线画布和帧率。4K 画布应为 3840×2160；帧率按用户要求或工单执行，不能因为源文件是 50 fps 就擅自改成 50，也不能无说明地降成 30。
7. 首次 AI 测试或风险较高的结构编辑必须复制时间线，在副本上执行；用户原时间线保持不动。正式版本已经由用户指定时，按正常写前刷新规则继续。
8. 提醒并记录本地源文件路径需要保持稳定。文件移动、重命名、磁盘离线或权限变化都可能导致桌面项目丢失媒体。

## 可用能力与不可用能力

| 能力 | `local-only` 结论 | 操作要求 |
|---|---|---|
| 项目、资产和时间线读取 | 可用 | 使用最新项目状态和真实 ID |
| 转写读取与脚本精剪 | 可用，已实测 | 写后重读时间线并检查连续性 |
| 字幕、贴图、MG、转场、裁切和轨道编辑 | 可用 | 每批写后做结构验证，并在桌面预览检查像素 |
| ChatCut Desktop 本地播放 | 可用，已实测 | 用于 `local-only` 的画面验证 |
| 云端时间线截图、云端画面渲染 | 不可用 | 不重复重试，不把它误报成编辑失败 |
| `pull_asset`、云端降噪、依赖源字节的服务端分析 | 不可用 | 需要时才向用户说明重新关联/上传 |
| 云端导出 | 不适用于本地主素材 | 走 ChatCut Desktop 本地导出 |
| 4K 最终导出 | 尚需逐项目验证 | 只有真实文件检查通过后才能标记成功 |

## 可见编辑的验证阶梯

### 1. 结构验证：每批必做

重读受影响的项目范围，检查画布、帧率、轨道、item、时间、源区间、字幕、贴图、MG、转场、间隙、重叠和轨道启用状态。结构验证不依赖云端素材字节。

### 2. 原始素材检查：只证明源文件

本地源文件存在时可以只读抽取源帧，用于检查拍摄清晰度、曝光或选择素材时刻。源帧不能证明时间线上的字幕、贴图、裁切、转场或 MG 正确。

### 3. 云端合成帧：素材远程就绪时优先

只有 `remote-ready` 才调用云端时间线截图。已经确认 `local-only` 后不要反复调用同一个必然失败的云端渲染任务。

### 4. 桌面预览：`local-only` 的正式替代证据

加载 `computer-use:computer-use`，控制 ChatCut Desktop，而不是用浏览器页面冒充本地桌面渲染。每次取证都要：

1. 刷新桌面应用状态，确认打开的是正确 `projectId`、时间线名称、画布和最新 revision。
2. 定位到受影响段落，暂停检查关键静帧；对剪点、转场、MG 和音频衔接必须实际播放前后区间。
3. 截取当前桌面预览画面并标记时间码、时间线、场景或 cue。桌面截图属于真实预览像素证据，但不是最终编码文件证据。
4. 按 [stage-audit-standards.md](stage-audit-standards.md) 保存所需场景帧、cue 帧、均匀帧和交接帧。若桌面工具无法精确定位或没有取得规定证据，只能报告“结构已验证”或“代表性桌面预览已验证”，不得宣称完整 S7/S9 像素审核通过。

云端截图失败时，正确动作是切换到这一桌面验证分支，并在结果中记录 `cloudVisual=unavailable(local-only)`；不得把失败响应伪装成视觉成功，也不得因此停止仍然可执行的时间线编辑。

## 本地 4K 导出与终检

1. 导出仍受“接触表已交用户过目并批准”的门禁约束。用户没有要求导出时，不因验证需要擅自导出完整视频。
2. `local-only` 主素材不提交云端导出。用户要求最终交付后，使用 ChatCut Desktop 本地导出；如当前宿主提供 Computer Use 且用户已经明确要求导出，AI 可以按 Computer Use 规则操作并观察桌面导出，否则给用户明确设置并等待本地文件生成。
3. 当前已知桌面 4K HDR/HLG 曾持续失败。默认先使用 **4K、SDR、与时间线一致的帧率**；只有用户明确需要 HDR 且短测试成功时才使用 HDR。不得把 SDR 自动改成 HDR。
4. 长片正式导出前检查可用磁盘空间。条件允许时先在复制时间线上制作包含字幕、贴图/MG 和转场的短代表段，用相同参数测试导出，再导出全片。
5. 导出文件可访问后，用 `ffprobe` 只读检查宽高、帧率、编码、时长和文件完整性；从真实导出文件只读抽取代表帧，检查清晰度、字幕、贴图、MG、转场、黑帧、黑边和错误裁切。不得用本地 ffmpeg 重新编码来“修复”或替代 ChatCut 导出。
6. 只有导出文件确认为 3840×2160、参数与工单一致且代表帧/播放检查通过，才能写 `4K实际导出验证通过`。导出失败时保留可编辑项目，记录失败设置与错误，不得降成 1080P 后仍声称完成 4K。

## 对用户的固定状态语言

最终汇报必须分别列出以下状态，不得合并成一个含糊的“验证通过”：

- `4K源素材确认通过`：原文件与 ChatCut 资产均达到目标分辨率。
- `编辑结构验证通过`：轨道、item、时间、字幕/贴图/MG/转场结构正确。
- `桌面预览验证通过`：ChatCut Desktop 的实际预览像素和播放检查通过。
- `云端画面验证不可用（local-only，非编辑故障）`：仅说明云端限制。
- `4K实际导出待验证` 或 `4K实际导出验证通过`：必须以真实导出文件为依据。

若只完成其中一部分，就只报告对应部分，禁止用“全部完成”“画面完全没问题”覆盖尚未取得的证据。
