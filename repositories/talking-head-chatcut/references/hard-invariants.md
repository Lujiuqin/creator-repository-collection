# 硬约束清单

这是 S5–S9 写入阶段唯一必须常驻上下文的文件。本 Skill 只走标准 ChatCut 工作流：不需要用户另行授权模式，也不使用旧版外部执行门禁。用户忠实度、画面安全、真实性、可编辑性、写前刷新、批次 dry-run、结构复读与合成帧验证仍是硬约束。

其余 references 按当前阶段单独加载，不要一次性全读。

风格、审美、模板选型的建议性内容不在这里 —— 它们不产生 fail，也不该占用执行注意力。

## 一、用户忠实度（契约：`assets/user-fidelity-rules.json`）

| # | 规则 | 校验点 |
|---|---|---|
| 1 | 每个场景记录 `fidelity`（verbatim / elaborated / ai-added）；verbatim 与 elaborated 带 `userSpecRef` 指向用户规划中的具体一行。 | 执行计划复读 |
| 2 | `deviations` 默认必须为空。任何偏离用户规划的点都要列在这里，且每条必须带 `userApproval`（用户原话 + 日期）。没有批准记录 = 硬失败。 | 用户规划对照 |
| 3 | 版式类型、PIP 有无与位置、用户点名的视觉机制、用户指定的 mustShowTerms、场景的合并/拆分/重排 —— 任一被改动且无批准记录即失败。 | 用户规划对照 + 合成帧 |
| 4 | 认为用户规划有问题时，唯一合法动作是记录待解决项并停下来问用户。不允许"先按自己理解改了再说"。 | 执行计划复读 |
| 5 | 全链路只允许一套场景编号，一次性登记在 `剪辑/scene-map.json`；任何文件不得私自重编号。 | 场景映射复读 |

## 二、屏幕状态（契约：`assets/screen-state-contract.json` → `canvasStates`）

| # | 规则 | 校验点 |
|---|---|---|
| 6 | 每个场景声明且只声明一个 `canvasState`：`L1-person` / `L2-media` / `L4-stage` / `transition`；相邻场景首尾相接，无空洞无重叠。 | 场景映射复读 |
| 7 | 每个场景必须声明 `baseLayer` 且 `coversFullCanvas=true`。画布任何时刻 100% 被基础层覆盖。 | 执行计划复读 + 合成帧 |
| 8 | `L4-stage` 下 MG 背景铺满全画布，底轨全屏 A-roll 必须 `hidden` 或缩进 PIP；禁止口播从不透明覆盖层下方露出。 | 结构复读 + S7/S9 帧级抽查 |
| 9 | 信息主区不得进入字幕禁区（16:9 `y ≥ 810`，9:16 `y ≥ 1560`）。 | S7/S9 帧级抽查 |
| 10 | PIP 必须完整包含人物头肩，不切头顶下巴；字幕、PIP、MG 主信息三者互不遮挡。 | S7/S9 帧级抽查 |

## 三、语义与时机

| # | 规则 | 校验点 |
|---|---|---|
| 11 | 每个信息单元都有词级 cue；可见响应落在 `-0.133s ~ +0.2s` 响应窗口内。 | 时间线复读 + `visual-sync-contract.json` |
| 12 | 结论不得比对应口播提前泄露超过 0.5 秒；段首不得一次性铺开后续整段文字。 | S7/S9 帧级抽查 |
| 13 | 每个动效/MG 必须声明 `purpose`：服务哪句口播的哪个理解任务（理解结构 / 强调重点 / 表达关系 / 定位操作 / 建立记忆点，五选一）。声明不出来的动效不做；用户规划里写了的动效天然有 purpose。 | 执行计划复读 |
| 14 | 没有理由加画面时，默认保持干净的真人全屏。**没有任何数量型密度指标**，不存在"必须凑够多少动效/多少版式"。 | 审美基线，无强制门槛 |
| 15 | 禁止装饰性常驻循环（漂浮、呼吸、闪烁、发光、网格移动、空准星）；循环只在内容表达循环/扫描/加载/实时检测时使用，并在语义状态结束时停止。 | S7/S9 帧级抽查 |

## 四、素材与真实性

| # | 规则 | 校验点 |
|---|---|---|
| 16 | 真实品牌 Logo、产品界面、事实证据必须来自官方原始资源或现场截图；禁止 AI 伪造。用户标注"必须真实录屏"的场景不得改用示意。 | `resource-policy.json` + 来源台账 + 合成帧 |
| 17 | 不允许非等比缩放、拉伸、裁掉关键区；`fitMode` 不得为 fill，`scaleX` 必须等于 `scaleY`。 | 结构复读 + 合成帧 |

## 五、成片技术底线

| # | 规则 | 校验点 |
|---|---|---|
| 18 | 无黑帧、无越界、无未收尾动画、无不匹配样式。 | S9 帧级抽查 |
| 19 | BGM 不压人声：口播段 BGM 相对人声至少低 18 LUFS-I 当量，整片 true peak ≤ -1.0 dBTP。 | `sound-profile.json` + S9 听审 |
| 20 | S9 终审通过后、导出前必须把接触表交给用户过目并取得批准记录；没有批准记录不得导出。 | `generate_contact_sheet.py` + 用户原话与时间记录 |

### 本地 4K 对以上规则的证据适配

- 本账号 4K 主母版默认由用户在 ChatCut Desktop 本地导入，详细流程见 [local-4k-workflow.md](local-4k-workflow.md)。在没有新的 4K 原样导入实测前，不得用插件导入路径替换主母版，也不得把 1080P 放大后声称满足规则 17。
- `local-only` 不是规则 18 的失败。它只说明云端没有源文件字节；时间线编辑继续执行，云端截图改由 ChatCut Desktop 真实预览取证。
- 桌面预览截图可以证明当前时间线的可见构图、字幕、贴图、MG、转场和播放连续性，但不能证明最终编码文件。规则 18 的“导出完成”结论仍须检查真实导出文件。
- 汇报时必须把 `编辑结构验证`、`桌面预览验证`、`云端画面不可用` 和 `4K实际导出验证` 分开。任何缺少证据的状态都必须保留为待验证。

## 违反时怎么办

技术类（响度、真峰值、黑帧、元数据）可以 `autoFixUntilPass`。
构图、版式、动效语义、用户忠实度类的 fail 修完必须重新读取 ChatCut 结构并检查实际合成帧；循环次数记录在案，超过 3 轮自动升级为向用户报告。
