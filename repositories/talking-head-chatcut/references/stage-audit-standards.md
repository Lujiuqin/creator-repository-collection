# 分阶段审核标准

每项标记 `pass` 或 `fail`。任一“硬失败”存在时先修正再进入下一阶段。验证证据必须来自当前项目状态，不得只复述制作意图。制作 Agent 直接使用 `chatcut:verification` 读取结构和合成帧；主素材为 `local-only` 时按 [local-4k-workflow.md](local-4k-workflow.md) 使用 ChatCut Desktop 真实预览像素作为替代证据。外部复审不是写入或导出的前置许可。

## 帧证据标准（S7 / S9 强制）

审核对象是"观众实际看到的帧"，不是文档。每次审核必须抽满以下四类帧，全部保存到 `剪辑/审核证据/<revision>/`，文件名含场景 ID 与帧号（例：`S04-frame-1620.png`）。**缺任何一张即审核无效**，不得以"其余帧都正常"为由通过。

| 类别 | 抽帧规则 | 用来查什么 |
|---|---|---|
| 场景帧 | 每场景至少 3 帧：进入中段、稳定中段、退出中段 | 屏幕状态合法性、基础层是否铺满、PIP 头肩、字幕禁区 |
| cue 帧 | 每个 `mustHonor` cue 三帧：`cue-0.25s` / `cue` / `cue+0.25s` | 词级响应是否真的发生、结论是否提前泄露 |
| 均匀帧 | 全片每 10 秒 1 帧 | 覆盖片长中段，防止只抽片头片尾 |
| 交接帧 | 每个非硬切转场的起点 / 中点 / 终点 | 承载元素连续性 |

本次事故的直接原因之一：终审只抽了片头片尾 15 帧，中间 80% 片长无人看过，S04 的构图错误因此漏检。

### 每帧必须核对的构图项

1. 画布是否被基础层 100% 覆盖；有没有口播 A-roll 从不透明覆盖层下方露出。
2. `L4-stage` 帧：MG 背景是否铺满全画布，底轨全屏 A-roll 是否已 `hidden` 或收进 PIP。
3. 信息主区是否进入字幕禁区（16:9 `y ≥ 810`，9:16 `y ≥ 1560`）。
4. PIP 是否完整包含头肩，是否与字幕或 MG 主信息重叠。
5. 该帧对应的用户规划行是否被忠实实现。

### 本地 4K 的证据解释

- `local-only` 导致云端截图报“没有源 URL”属于已知能力边界，不是素材损坏、编辑失败或硬失败；同一个云端任务不重复重试。
- S0 必须先证明原文件和 ChatCut 资产均达到目标分辨率。只有画布是 3840×2160、资产却是 1920×1080 时仍按 4K 继续，才是硬失败。
- S3、S6、S7 和导出前 S9 可以使用 ChatCut Desktop 的定位静帧与实际播放截图完成像素审核。截图必须注明 `desktop-preview`、时间码、时间线和 revision，且仍须抽满本节规定的场景/cue/均匀/交接帧。
- 桌面预览证明当前时间线画面，不证明最终编码文件。没有检查真实导出文件时，S9 最多标记为“桌面预览通过、达到可导出状态”；不得标记“4K 实际导出通过”。
- 真正完成 4K 导出后，必须用 `ffprobe` 证明文件为 3840×2160 且帧率、时长符合工单，并从该文件抽取代表帧做最终检查。

## S0 项目与素材

- 通过：项目 ID、画布、目标画幅、帧率、时长和主口播轨确认无误；素材清单完整；重复素材已识别；用户已有编辑未被覆盖；本地 4K 项目另已记录源文件与 ChatCut 资产分辨率、`remote-ready|local-only` 和源路径稳定性。
- 硬失败：选错项目；主口播缺失；目标画幅未确定；重复素材被当作新段落；导入后音画损坏；用户已有编辑被覆盖；目标为 4K 却使用低于目标分辨率的主资产并靠画布放大；AI 用插件重新导入并替换用户桌面版 4K 主母版。
- 证据：项目摘要、轨道摘要、素材清单和重复项说明；本地 4K 另附 `ffprobe` 摘要、ChatCut 资产尺寸和 readiness 状态。
- 自动修正：撤销错误导入或时间线放置，重新定位正确项目和主素材。

## S1 ASR 与专名

- 通过：专名、英文缩写、数字、单位和关键术语与脚本/画面一致；标点不改变语义；时间码仍对应音频。
- 硬失败：把正确口播“润色”成新观点；专名仍有错；字幕文本与实际发音错位。
- 证据：原词 -> 修正词 -> 时间码 -> 依据的校正表，以及高风险专名抽听。
- 自动修正：恢复原句语义，按上下文和画面重新校正；无法确定时保留原音并标记低置信度。

## S2 口播精剪与人声基础处理

- 通过：口误、重复、无意义语气词和无价值长停顿已处理；保留原意；默认 1.1 倍速且保持音高；人声增强已启用并使清晰度提升；剪点与处理痕迹听不出明显断裂。
- 硬失败：语义缺失、句子拼接错误、喘息被切断、1.1 倍速导致吞字、未启用人声增强且无失败说明、跳过任一必检语段的人声增强试听、人声增强造成泵动/金属感/齿音放大、画面跳切无法接受。
- 证据：删除/保留决策、精剪前后时长、速度与保持音高设置、人声增强设置、开头/中段/最轻人声/所有高风险剪点的前后至少 1 秒试听。
- 自动修正：恢复必要词或气口；移动剪点；局部降低速度；降低人声增强强度；用已规划素材/MG 遮挡明显跳切。

## S3 字幕

- 通过：字幕内容正确、标点自然、断句合理、字号可读，使用当前画幅的字幕安全区，与人脸和画面主体不冲突。
- 硬失败：缺字错字；时间不同步；套用错误画幅字幕参数；超过两行持续遮挡；使用逐字当前词高亮；单条字幕超过 1 个重点单元、重点字符超过 35%，或连续超过 2 条字幕使用重点标识。
- 证据：开头、中段、结尾、最快语段和专名语段截图/预览。
- 自动修正：重新对齐；缩短单条；调整断行、字号、位置、描边和重点词样式。

## S4 画面规划

- 通过：已读取当前项目状态、精剪时间码、用户原始画面规划和可用素材，形成当前执行计划。计划记录每个关键语义段的 `viewerJob`、信息结构、目标画幅、`sceneTemplate` 或明确的 bespoke 路径、真实内容、词级 cue、`processContinuity`、素材和风险。每个相邻场景都有兼容的 `transitionInstance` 或显式硬切；用户脚本中的画面标注全部保存为 `mustHonor userOverride`。存在 ShotCraft 引用时，`designReferences` 已记录固定来源、适配方式、必保动作和删弃实现，且没有改变模板身份或事实来源。
- 视觉编排补充通过：逐场主轮廓、模板运动签名、路径、信息保留方式、视觉材料和状态变化帧可核对；每个动效都声明了 purpose。转场记录语义 intent、承载对象和起点/中点/终点证据。**不设多样性下限**。
- 硬失败：按固定秒数猜节奏；没有词级 cue map；执行计划与当前项目、最终脚本或用户画面规划冲突；模板缺少绑定运动签名；模板或原语越权；`cueFrame` 公式错误；存在没有声明 purpose 的动效；场景缺少 `canvasState`/`baseLayer` 或屏幕状态非法；场景 `fidelity`/`userSpecRef`/`deviations` 缺失；存在无用户批准记录的降权；场景编号未登记在 `scene-map.json`；转场角色不兼容；需要连续的承载对象断裂；用户指令未落实或覆盖污染未指定分面；画面提前揭示或延后解释；双画幅变体缺失；真实 Logo/UI/证据被规划为 AI 生成；同一时刻多个主焦点；连续滥用 `L3`；无语义循环；用模板或外部镜头卡反向改写用户画面描述；把 ShotCraft 卡写成 `templateId`、`sourceMode` 或事实来源。
- 视觉编排硬失败：连续三个场景同轮廓；相邻场景同轮廓同运动签名；相邻转场重复相同 intent 和承载对象；硬切占比超过 30% 且无语义说明。
- 证据：当前项目摘要、执行计划、cue map、用户覆盖清单、模板/转场映射、外部设计引用、资源来源或生成简报，以及横竖屏代表帧。
- 自动修正：回到精剪词级时间码和原句重排场景；补齐实例、转场、覆盖和资源策略；换成语义匹配模板或 bespoke；把事实画面切换到真实来源；拆开冲突主运动窗；增加有意义的中段状态推进；替换不忠实的模板或转场。

## S5–S9 共同写入验证

- 通过：每批写入前确认当前 `projectId`、`timelineId`、画布和受影响轨道；破坏性或大批量操作先 `validateOnly`；写入后重读受影响结构并检查实际合成帧。发现用户手改或 revision 变化时，先重新读取真实项目状态，再更新坐标、item ID 和后续批次。`local-only` 使用当前 revision 的桌面预览像素替代云端合成帧。
- 硬失败：使用陈旧项目、时间线、画布、坐标或 item ID 写入；大批量操作未做 dry-run；只根据工具成功响应宣称视觉完成；结构性时间变化后仍复用旧绝对帧；发现用户手改后覆盖其编辑而未重新读取。
- 证据：每批写入前后的项目/时间线摘要、`validateOnly` 结果、写入结果、结构复读和受影响范围的云端合成帧或带时间码的桌面预览截图。S9 另须有最终全片复审和接触表。

## S5 模板与素材准备

- 通过：已经读取当前项目、Design Style 与统一模板库；场景模板和转场模板评分至少 8/10，适配画幅、画面描述、运动签名、转场端口和 cue map；低分或用户特殊需求已明确走 bespoke。每个 ShotCraft 引用已读取固定 commit 的配方卡和准确 demo，完成 ChatCut 适配路线与授权判断。官方 Logo/真实截图/公共资源已核实导入，生成路线与来源台账完整。
- 硬失败：硬编码失效模板 ID；低于 8/10 仍强行套用；静态结构与动作分开随意搭配；转场与前后角色不兼容；用户明确画面要求被模板覆盖；未读准确 ShotCraft demo 就凭卡名重写；安装或运行 Remotion；把 Ink Press、假 UI、示例数据、来源不明音频或压平渲染当作 ChatCut 素材；搜索缩略图或来源不明资源直接入选；AI 生成真实 Logo、产品 UI 或事实证据；来源台账缺失；临时热链、隐私泄露或无关装饰素材；全片只重复少数运动签名或转场。
- 证据：场景模板/实例/转场/用户覆盖/素材映射、模板评分、运动签名、转场连续性合同、外部卡片 commit/配方/demo/适配记录、资源原始 URL/发布者/获取日期/使用依据、项目 `assetId` 和候选新机制说明。
- 自动修正：换成官方/原始来源并重新导入；补齐台账；删除隐私内容；把伪事实素材改为真实截图、MG 或明确示意；换模板、选择不同信息机制或直接制作新 MG。

## S6 素材插入与生成

- 通过：素材出现和消失都对准语义锚点；每个目标画幅的裁切与主体正确；全屏/框内/缩放标注模式合理；字幕安全区完整；真实 Logo、真实 UI 和事实证据均来自核实后的真实资源，未使用 AI 生成；新 AI 图片由 Codex `imagegen` 生成、保存到稳定本地路径并导入 ChatCut；AI 图片/视频的主体、身份、风格、运动和首尾帧通过检查；项目资产与台账一致。
- 硬失败：关键内容被裁掉；横竖屏沿用同一错误裁切；素材早于口播结论；资源与脚本或当前执行计划冲突；新 AI 图片没有使用 Codex `imagegen` 或调用了 `chatcut:image-gen`；使用 AI 生成真实 Logo、真实 UI 或事实证据；AI 示意图被当作事实证据；生成素材存在严重脸手/物体变形、漂移、闪烁、文字或 Logo 幻觉；多镜头身份未使用一致性锚点；并发提交多个 AI 视频生成任务；绕过 ChatCut AI 视频付费生成、范围对齐或结果复核规则；重新裁切/放置后暴露私密信息；来源台账缺失或与项目 `assetId` 不一致；Codex 图片未保存到稳定项目路径；时间线引用未导入资源、临时生成路径或临时热链。
- 证据：素材入点、出点、锚点文字、关键帧截图、来源/生成台账、Codex 图片稳定本地路径或 ChatCut 视频 `jobId`、提示摘要、参考资产、参数、结果复核和项目 `assetId`。
- 自动修正：重设入出点、裁切、缩放、遮罩和标注；替换来源；重新生成或改用参考锚点；连续两次文字修正无效时切换锚点/编辑模式或放弃该素材。

## S7 MG 与词级视觉同步

- 通过：MG 按当前执行计划的 `sceneTemplate.motionSignature` 与 `sceneInstance` 创建；信息按词级 cue 执行 reveal/highlight/state-change/media-focus，口播中段持续推进语义状态；每个动效都能对上它声明的 purpose。每个 `transitionInstance` 按起点、中点、终点证明前后状态和承载对象连续；用户覆盖有真实像素证据。引用 ShotCraft 时，必保动作在 ChatCut 合成帧中可感知，原 TSX/import/fixture/本地资源依赖已移除。层级、字幕、PIP、安全区、双画幅和可编辑属性完整。
- 视觉编排补充通过：品牌统一，但缩略接触表中的主构图、运动签名、持续过程和转场可感知地区分；相邻去重复；素材按时退出。没有理由加画面的段落保持干净全屏口播，这是合格状态。
- 硬失败：静态结构与动画分开套用；段首整段抢跑；cue 提前或滞后超过 0.5 秒；存在没有声明 purpose 的动效；出现装饰性常驻循环；highlight 无主次变化；media-focus 无具体对象；无语义循环未停止；同一时刻多个主焦点；转场硬切人物、对象瞬移、裁切跳变或中间黑帧；用户标注未实现；引用卡片却缺失动作命门仍宣称复现；MG 含 Remotion import、Sequence、fixture、硬编码素材 URL 或不可编辑可见值；只凭代码参数判定通过；横竖屏拉伸；遮挡、越界、跨场景污染或不匹配复用。
- 视觉编排硬失败：连续三个场景同轮廓；相邻同轮廓同运动签名；相邻转场重复 intent 和承载对象；硬切占比超限；连续承载对象身份断裂。
- 证据：每个 cue 的前/中/后合成帧；模板进入、持续过程、稳定和退出帧；每个转场起点/中点/终点；ShotCraft 必保动作逐项对应帧；highlight 三态、media-focus 三态、最长静止区间、运动覆盖摘要、用户指令对应帧、全片接触表和最后真实帧。
- 软失败：主要视觉响应落在质量目标窗外、但仍未达到提前/滞后 0.5 秒硬失败线时，先自动调整；只有存在可感知的合理原因（例如长音节、必要视觉预备动作）并记录合成帧证据时才可通过。
- 自动修正：从精剪转写重算 cue；在 `reveal` 与 `highlight` 间按规划切换；增加有意义的节点、标注或状态推进；调整锚点、持续时间、层级、栅格、字号和动画曲线；必要时简化内容或创建新的视觉机制。

## S8 音频

- 通过：人声始终清楚；BGM 稳定；转场和内容音效音色有变化、密度克制且落点准确；普通扬声器低音量下关键内容音效仍可稳定辨识；结尾有收束。
- 硬失败：BGM 压人声；关键内容音效在普通扬声器低音量下不可辨识；音效连续轰炸；同一种音效机械重复；音效比画面早/晚；没有对应画面响应却只提高音量；爆音、削波、泵动、遮住口播首字或突兀断尾。
- 证据：关键段试听记录、普通扬声器低音量试听记录、各音频轨用途和增益摘要、提高音效前后的分层增益表及峰值/削波检查。
- 自动修正：降低/自动闪避 BGM；先补齐缺失的画面 cue；按 `sound-profile.json#sfx.userFeedbackAdjustmentDb` 分层提高；删减过密音效，轮换音色，移动落点并加短淡入淡出；若出现峰值风险只回退最强音效。

## S9 最终复审与导出
