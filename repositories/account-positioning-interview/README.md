# 通用账号定位官

> 一个面向新手的 Codex Skill：先读取工作区已有资料，再通过一次一个问题的渐进访谈，建立可追溯、可长期维护的账号背景与内容定位。

`account-positioning-interview` 不要求你懂“账号定位”“商业模式”或“用户画像”这些术语。它会从你最近做过的事、真实交付、客户问题和内容意愿开始，逐步梳理：谁在运营账号、你能讲什么、当前有什么产品、目标用户是谁，以及账号准备长期讲什么。

整个过程中，AI 只会把你确认过的内容写入正式文件。没有产品可以如实写“暂无”；证据不足的用户判断会标为“待验证用户假设”；目标和计划不会被写成已经实现的结果。

## 它能帮你完成什么

1. 整理个人、品牌、团队或组织账号的真实背景与能力依据。
2. 梳理当前产品、服务、业务承接方式和不能承诺的边界。
3. 从客户、咨询、评论、访谈或本人经验中提取目标用户与真实需求。
4. 共同确认账号主题、主要受众、核心价值、表达视角、人设和 2—4 个内容方向。
5. 在当前工作区创建或更新五份标准 Markdown，让新的 AI 会话能快速读懂账号。
6. 更新旧定位时识别缺口、过期信息和冲突，不要求你重复回答已有资料能够确认的内容。

## 适合谁

- 第一次梳理个人或内容账号，不知道从哪里开始的人；
- 手里有零散经历、产品、客户和内容资料，但没有统一事实入口的人；
- 已有旧定位，需要补缺、更新或处理冲突的人；
- 希望后续 AI 创作建立在真实背景和清楚边界上的个人、品牌、团队或组织。

## 它不会做什么

- 不默认平台、赛道、内容形式、商业模式或变现目标；
- 不要求安装 Obsidian，也不要求固定目录结构；
- 不替用户编造经历、成绩、案例、用户需求、产品或商业结果；
- 不替没有产品的用户强行设计课程、社群或咨询服务；
- 不生成正式选题、正文、平台简介、头像或主页包装；
- 不自动发布内容、发送消息、提交代码、购买或删除资料。

## 安装方法

把下面这段话发送给 Codex：

```text
请使用 skill-installer 安装这个 GitHub Skill：
https://github.com/wangguoqing123/account-positioning-interview
```

也可以手动把仓库克隆到 Codex Skills 目录：

```bash
git clone https://github.com/wangguoqing123/account-positioning-interview.git \
  ~/.codex/skills/account-positioning-interview
```

安装完成后，下一个对话轮次即可使用该 Skill。

> 本 Skill 主要面向支持本地 Skills 的 Codex。其他 AI 工具能否直接使用，取决于它们是否兼容同类 Skill 目录和指令格式。

## 使用方法

在需要建立账号资料的项目目录中打开 Codex，然后说：

```text
使用 $account-positioning-interview 帮我梳理个人背景、产品、目标用户和账号定位，并写入当前项目。
```

如果一个工作区有多个账号，Skill 会先让你选择本轮只处理哪个账号。随后按五个模块逐步进行：

```text
读取已有资料并确定唯一输出目录
→ 个人与账号事实
→ 产品与商业承接
→ 目标用户与真实需求
→ 账号定位与内容方向
→ 生成个人背景总览并回读核对
```

一次只会提出一个主要问题，最多带一个紧密相关的追问。每个模块信息足够后，AI 会先展示摘要；你确认或纠正后，才写入对应文件。

你可以直接回答“暂无”“不知道”“不确定”或“以后补充”。这些内容会如实保留，不会被 AI 自动补造。

## 标准输出

Skill 固定维护五个逻辑文件：

```text
个人与账号事实.md
产品与商业承接.md
目标用户与真实需求.md
账号定位与内容方向.md
个人背景总览.md
```

输出位置按以下顺序确定：

1. 优先使用用户指定的当前工作区内目录；
2. 其次复用已有的 `00_个人背景/`、`个人背景/`、`账号资料/`、`品牌资料/` 等等价目录；
3. 没有合适目录时，在当前工作区创建 `个人背景/`。

五份文件只会放在一个目录中，避免同一账号出现多套互相冲突的定位资料。已有其他定位文件只作为事实来源，不会被移动、删除或静默覆盖。

## 信息如何标记

为避免把推断写成事实，访谈内容会区分：

- **已确认事实**：用户明确陈述并确认，或来自用户认可的具体资料；
- **本人判断**：用户当前认可的方向、态度和选择；
- **意愿目标**：希望未来实现，但尚未实现的结果；
- **AI 建议**：基于现有信息提出的候选，不属于用户事实；
- **待核查**：方向明确，但证据、时间、版本或范围尚未确认；
- **暂缺**：当前没有信息，可以以后补充。

每份文件还会保留版本、最后确认时间、待核查项、来源记录和变更记录。

## 和 `shengcai-positioning-interview` 的区别

| Skill | 适用范围 | 固定赛道或平台 | 主要输出 |
| --- | --- | --- | --- |
| `account-positioning-interview` | 任意个人、品牌、团队或组织账号 | 不固定 | 账号事实、产品、用户、内容方向和总览五份文件 |
| `shengcai-positioning-interview` | 8 月生财航海家定位关卡 | AI 自媒体与小红书 | 航海关卡定位和账号包装 |

两个 Skill 相互独立。本仓库不会修改或替代生财航海专用版。

## 仓库结构

```text
account-positioning-interview/
├── README.md
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── interview-guide.md
    ├── location-strategy.md
    └── output-files.md
```

- `SKILL.md`：目标、边界、五模块流程、写入规则和完成标准；
- `agents/openai.yaml`：Codex 中显示的名称、简介和默认启动提示词；
- `references/interview-guide.md`：小白访谈方法、追问方式和各模块信息充足标准；
- `references/location-strategy.md`：如何选择唯一输出目录并避免重复文件；
- `references/output-files.md`：五份标准 Markdown 的字段与版本规则。

## 维护原则

- 真实信息优先，AI 建议不能伪装成用户事实；
- 已有资料优先，只追问缺口和冲突；
- 一次只处理一个账号；
- 每个模块先确认、后写入；
- 更新已有文件时保留用户手动维护的无关内容；
- 写入后回读五份文件，核对路径、标题、链接、状态和待确认项。
